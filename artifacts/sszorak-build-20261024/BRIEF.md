# 단일 딜사이클을 스조라크 상위 기록의 "빌드" 기준으로 다시 짜기 (2026-10-24 2차)

## 왜 하는가
- 사용자 원문(이번): "단일은 무조건 스조라크 로그로 고쳐줘"
- 바로 앞 사용자 지적: "단일 딜사이클은 단일 특성 기준으로 해야하는데 (예. 조화 드루이드는 천벌3회 - 나무 - 정렬 - 쇄도 3번 - 영혼소집 이런식으로) 실전 로그와 괴리감 있는 문서들이 많은데?"
- 지난 1차 작업(`../sszorak-cycle-20261024`)의 구멍 두 가지:
  1. 영웅 탭마다 순서만 맞췄고, **처음 열리는 영웅 탭·단일 견본이 스조라크에서 거의 안 쓰는 영웅 특성**이었다(조화·야성·파멸·풍운·고통·암흑·포식). 그래서 처음 보이는 단일 딜사이클이 실전과 다르다.
  2. **같은 스킬을 이어 쓰는 횟수**를 한 칸으로 합쳐 버렸고(예: 별빛쇄도 3~4번 → 한 칸), 단일 순서에 **광역기**(별똥별 등 "3대상 이상이면 대신")가 섞였다.
- 이번에 정한 방식(사용자가 승인):
  1. 스조라크 상위 기록에서 가장 많이 쓴 **영웅 특성과 특성 선택**을 그 가이드의 단일 기준으로 삼는다.
  2. **오프닝과 단일 반복**을 그 기준으로 다시 짜고, **반복 횟수를 표시**하며(예: 별빛쇄도 ×3), **단일 순서에서 광역기를 뺀다**.
  3. 단일 특성 견본을 스조라크 랭킹 특성으로 다시 만든다 → **이미 만들어 두었고 apply-patch 가 자동으로 넣는다**(원고에서 따로 고치지 않음).
  4. **쐐기와 광역은 그대로** 둔다.

## 이미 정해 둔 것 (작업자가 바꾸지 않음 — apply-patch 가 자동 처리)
- 가이드별 단일 기준 영웅 특성: `dominant.json` (스조라크 신화 12.1.5 구간 상위 랭킹 ALL·KR 행 수가 많은 쪽).
- **기본 영웅 탭**(`decisions.json`): 처음 열리는 탭의 첫 화면이 '오프닝'(레이드 단일 풀링)이라, 처음 열리는 탭을 단일 기준 영웅 특성으로 바꾼다. 바뀌는 가이드 7개: 조화(→숲의 수호자)·야성(→야생추적자)·파멸(→알드라치 파괴자)·풍운(→천신의 대변자)·고통(→지옥소환사)·암흑(→공허술사)·포식(궤멸자→공허상흔, 상위 10위 안 10개·상위 50 중 44개가 공허상흔). 나머지 20개는 이미 맞다.
- **단일 견본**(single-target): `build-diff.json`(대표 빌드·지금 견본과 다른 칸) + 계산기 확인 `calc-sszorak.json`(25개 모두 34/34/13, 끊긴 칸 없음). 분노·냉기 마법사는 지금 견본과 같은 코드. 레이드 견본 코드는 그대로 두고 "같은 견본" 설명만 자동으로 고친다. 쐐기 견본은 건드리지 않는다.
- 기준 영웅 탭의 오프닝·단일 탭에 "특성 견본: 단일 견본 기준" 링크(`talentBuildId: 'single-target'`)를 자동으로 붙인다.
- 화면에 안 나오는 상단 `opener` 는 기본 탭 오프닝과 같았던 가이드면 자동으로 새 기본 탭 오프닝으로 맞춘다.
- 화면 기능: 타임라인 칸(rail node)과 영웅 탭 오프닝 단계(opener.steps)에 **`count`** 필드를 새로 쓸 수 있다. `count: 3` 또는 `count: '2~3'`(2 이상, 뒤 숫자가 더 큼). 타임라인에서는 아이콘 오른쪽 아래에 `×3` 표시, 영웅 탭 오프닝에서는 이름 옆에 `×3` 이 붙는다. 위쪽 가지(above)·단일 우선순위(priority)에는 쓰지 않는다.

## 무엇을 고치나 (`patches/<ID>.cjs` 하나로)
1. **오프닝** — 2부 오프닝 장 타임라인의 기준 영웅 특성 rail, 기준 영웅 탭 `opener.steps`(+title·summary).
   - 기준 영웅 특성 로그 **과반의 실제 순서**로 짠다. 같은 스킬을 이어 누르면 칸 하나에 `count` 를 단다(로그마다 다르면 '3~4'처럼 범위, 과반이 같은 수면 그 수). 칸을 쪼개 같은 아이콘을 여러 번 놓지 않는다.
   - 프리풀(전투 전)은 1차 규칙 그대로: 심크 precombat 과 Icy Veins·Method 중 하나 이상이 같은 쪽이거나 로그 음수 초 과반일 때만. 기준 영웅 특성이 바뀐 가이드는 그 영웅 특성 기준으로 다시 확인한다(예: 조화 숲의 수호자는 precombat 천벌 ×3 — `dream_surge` 조건 확인, 사용자 예시도 천벌 3회). 단계 `phase: '전투 전'`, `trigger: '풀링 N초 전'`.
   - 단일 오프닝에서 **광역 갈래를 뺀다**: "3대상 이상이면 별똥별", "여러 대상이면 …" 같은 칸·위쪽 가지·단계·문장. 대상 수에 따라 갈리는 설명은 광역 장(그대로 둠)으로 미룬다.
   - 오프닝 장 rail 순서는 기준 영웅 특성 rail 을 맨 앞에 두고, 이름표의 '(기본)'도 기준 영웅 특성 쪽으로 옮긴다. 다른 영웅 특성 rail 은 순서를 바꾸지 말고 광역 갈래만 뺀다.
   - 지금 오프닝이 이미 로그 과반과 같으면 순서는 두고 `count` 만 단다. 억지로 고칠 거리를 만들지 않는다.
2. **단일 반복** — 2부 단일 장 타임라인(반복 흐름 rail + 끼워 넣기 rail), 기준 영웅 탭 `singleTarget.priority`(+title·summary).
   - 반복 흐름 rail 이 다른 영웅 특성 기준이면(예: 조화 "엘룬의 대행자 기준") **기준 영웅 특성 기준으로 새로 짠다**. 다른 영웅 특성 고유의 것은 끼워 넣기 rail 로 옮긴다(이름표에 영웅 특성 이름).
   - 반복 rail 의 `count` 는 `bd` 의 '이어서 누른 횟수'가 꾸준할 때만(중앙값 2 이상이고 사분위가 좁을 때). 들쭉날쭉하면 달지 않는다.
   - 단일 우선순위·반복 rail 에서 광역기 행·칸을 뺀다(광역 탭·광역 장은 그대로). 기준 영웅 특성·새 견본에 없는 특성의 버튼은 "골랐다면" 행으로 남기거나 뺀다(새 견본의 선택 칸은 `bd` 의 '둘 중 하나 고르는 칸'으로 확인).
3. **글** — 같은 순서·같은 영웅 특성을 말하게 맞춘다. 고친 순서와 어긋나는 문장을 남기지 않는다.
   - 2부 단일·오프닝 장의 concept·paragraphs·bullets·mistakes·quiz·example·aside·cards·diagram, rail note(근거 문장 — "스조라크 신화 상위 기록 10개 중 9개가 …"처럼 수를 쓴다).
   - 영웅 탭 `summary`·`bullets`: 기준 영웅 특성 탭에는 스조라크 상위 기록 근거(예: "스조라크 신화 상위 198행 중 193행")와 단일 네임드용이라는 점, 다른 탭에는 그 영웅 특성이 어디에 맞는지(쐐기·쫄이 섞이는 레이드 등 — `bd` 의 님리사·쐐기 분포가 근거)를 쓴다. "단일과 대부분의 쐐기 기본", "이번 한국 검수: 레이드 1건" 같은 낡은 문장은 고친다. 영웅 탭 bullets 는 검사기가 1번 플레이 변화·2번 콘텐츠/로그 맥락·3번 실수·4번 로그 확인 점으로 본다(형식 유지).
   - 1부·3부·4부 글 가운데 **기본 영웅 특성·단일/레이드 영웅 특성 선택·단일 순서**를 말하는 문장(예: "현재 기본인 엘룬의 대행자는", "레이드는 집정관")만 최소한으로 고친다. 3·4부 영웅 특성 장의 위치(부)와 순서는 바꾸지 않는다. 장 제목은 2부 단일·오프닝 장(':' 앞 머리말 유지)과 3·4부 영웅 특성 장(그 영웅 특성 이름 유지)만 바꿀 수 있다.
4. 지난 1차 보류 중 이번 방식으로 풀리는 것은 처리한다(예: 파멸 알드라치 영웅 탭 오프닝을 단일 순서로 — 검사기가 막으면 아래 '검사기 고칠 곳'에 적는다). 다른 영웅 특성(기준이 아닌 쪽)의 보류(분노 산왕, 냉기 서리불꽃 등)는 그대로 둔다.

## 건드리지 않는 것
광역 타임라인·`aoe` 탭·탱사이클, 쐐기 견본·레이드 견본 코드, 영상(video), 출처(sources), book, 상단 `priority`, logReview, 현장 팁(fieldTips)·인용·장별 sources, 0부 skillGroups, 장 수·부·순서, 영웅 탭 이름·skillIds, 포식(demonhunter-devourer) 두 영웅 특성 오프닝 첫 두 단계 '풀링 1초 전 영혼 제물 → 흡수로 풀링'(사용자가 정한 순서). 다른 가이드·공용 파일(GuideDetailPage.js, 검사기, guideManuscripts.js, apply-patch.cjs 등)도 건드리지 않는다. 원고 파일·KB json 을 손으로 고치지 않는다.

## 규칙 (어기면 안 됨)
- skillId 는 `C:/wowmeta/site/src/data/kb-skills.json` 에 있는 것만. 찾기: 사이트 폴더에서 `npm run kb:brief -- <ID> --find <낱말>` / `--id <번호>`. KB 에 없는 스킬이 꼭 필요하면 **KB 노트를 직접 만들지 말고** 보고서 "KB 추가 필요"에 적는다(이름·번호·이유). 임의 번역 금지. 스킬 설명(툴팁)은 고치지 않는다. 문장에서 스킬은 KB 한국어 이름 그대로 쓴다.

- 쉬운 존댓말, 짧은 문장, 번역투 금지, 영어 원문 인용 금지. 지금 원고의 말투를 따른다.
