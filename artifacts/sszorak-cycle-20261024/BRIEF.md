# 단일 딜사이클을 스조라크 상위 로그 기준으로 (2026-10-24)

## 왜 하는가
사용자 원문: "스조라크 네임드가 단일 네임드니까 단일 딜사이클은 (프리풀은 심크 apl 및 타 가이드 사이트 참고) 상위 스조라크 네임드 로그 기준으로 고쳐야해 모든 딜러군"

지난 대조(2026-10-20, `../cycle-order-20261020`)의 레이드 근거는 신화 님리사였다. 님리사는 쫄이 나와 단일 순서에 광역기가 섞였다. 이번에는 **단일 네임드 스조라크(신화, 12.1.5 구간)** 상위 로그로 **단일 딜사이클(오프닝 + 단일 반복)** 을 다시 맞춘다. 대상은 딜러 27개(탱커·힐러 제외). **광역·쐐기·탱사이클·특성 견본·기본 영웅 탭은 범위 밖**이다.

   - 영웅 트리별 전 지역 상위 8 + KR 상위 3(중복 제외) 전투의 실제 시전, 풀 8초 전부터. 원본 `events/`.

2. **프리풀(풀링 전) = 심크 우선순위 precombat + 공개 가이드** — `apl/<직업_전문화>.simc`(simc midnight 3af1a757, 2026-10-23; 파일별 마지막 수정일 `apl/LAST-COMMITS.txt`), `sources/<ID>.txt`(Icy Veins 딜사이클 페이지·Method 플레이스타일 페이지에서 오프닝·프리풀 부분만 발췌, 원본 HTML `sources/<ID>-icy.html`·`-method.html`). 로그의 음수 초(풀 전 사전 시전)도 근거로 같이 본다.
3. 원고에 이미 있는 공개 가이드 출처(`views/<ID>.json`의 sources·evidence)는 보조.

## 판단 기준
- **오프닝(풀링 뒤)**: 같은 영웅 특성 스조라크 로그의 **과반**이 가이드와 다른 순서면 고친다. 갈리면 많은 쪽을 기본으로 두고 rail note 에 "로그마다 다름"을 짧게 적는다. 1~2개만 다르면 고치지 않는다.
- **프리풀**: precombat 에서 실제로 누르는 행동(사전 시전 주문, 풀 직전 쿨기·버프·은신 등) 중 심크 우선순위와 공개 가이드(Icy Veins·Method 중 하나 이상)가 같은 쪽을 가리키거나, 로그 음수 초에 과반이 보이는 것만 오프닝 맨 앞에 둔다. 영웅 탭 opener.steps 행은 `phase: '전투 전'`, `trigger: '풀링 N초 전'`(초는 공개 가이드·로그로 확인된 만큼만, 모르면 '풀링 직전'), 연습 장 rail 노드 caption 도 '풀링 N초 전'처럼 짧게. 이미 있는 프리풀 단계가 근거와 맞으면 그대로 둔다.
  - 넣지 않는 것: 영약·음식·물약·장신구·snapshot_stats·variable 같은 준비, 전투 내내 유지하는 상시 버프(독, 전투의 외침, 소환수 소환 등)는 노드로 넣지 않는다(필요하면 note 문장 한 줄).
  - **포식(demonhunter-devourer) 오프닝 첫 두 단계 '풀링 1초 전 영혼 제물 → 흡수로 풀링'은 사용자가 정한 순서다. 두 영웅 특성 모두 그대로 둔다.**
- **단일 반복**: '다음에 누른 스킬' 표·반복 예시·분당 시전·심크 우선순위로 판단. 가이드가 A→B 인데 로그가 꾸준히 B→A 면 고친다. 분당 1회 이상 누르는 핵심 버튼이 반복 rail·영웅 탭 단일 우선순위에 없으면 넣는다(조건은 심크 우선순위로 확인). 가이드에 있는데 로그에 거의 없는 버튼은 다른 시전 번호·자동 시전·피해로 찍히는지 확인하고 판단한다(예: 시전 0회만 보고 빼지 말 것 — 불지옥 일격처럼 시전 기록에 안 남는 스킬이 있다).
  - 로그 해석 주의: 자동으로 나가는 시전(예: 칼날폭풍 중 불안정한 정신의 필사의 일격)·소환수 시전·장신구·물약·생존기·이동기(돌진·영웅의 도약·주문 반사 등)는 딜사이클 순서로 보지 않는다.
- **스조라크 로그가 없는 영웅 특성**(digest 에 '로그 없음'): 풀링 뒤 순서·단일 반복은 바꾸지 않는다. 프리풀은 심크 우선순위·공개 가이드가 그 영웅 특성에도 맞는다고 확인될 때만.
- 두 영웅 특성 **공통 반복 rail** 은 로그가 있는 영웅 특성 기준으로 공통 부분만 고치고, 영웅 특성 고유 순서는 inserts rail 이나 영웅 탭에 둔다.
- 확실하지 않으면 바꾸지 말고 보고서에 "보류"로 적는다. 맞는 가이드는 "변경 없음"이 정답이다. 억지로 고칠 거리를 만들지 않는다.

## 고치는 곳 (모두 같은 순서를 말해야 한다) — `views/<ID>.json` 으로 본다
- 2부 연습의 **단일 장 타임라인**(반복 흐름 rail + 영웅 특성별 끼워 넣기 rail)과 **오프닝 장 타임라인**(영웅 특성별 rail).
- 영웅 특성 탭 `heroBranches[i].opener.steps`(+ title·summary) / `singleTarget.priority`(+ summary). 각 행 기존 필드(skillId, label, note, phase, trigger) 유지.
- 같은 장의 한 줄 원리(concept)·본문·요점·실수·확인 문제·rail note 가 순서를 말하면 함께 고친다. 3부 영웅 특성 장·공격대 장에 단일·오프닝 순서 문장이 있으면 맞춘다. **고친 순서와 어긋나는 문장을 남기지 않는다.**
- 단일·오프닝 rail note·영웅 탭 note 에 지난 근거(님리사 레이드 기록 n개 등)로 단일 순서를 설명한 문장이 있으면 스조라크 근거로 바꾼다. 예: "스조라크 신화 상위 로그 11개 중 9개가 …". 광역·쐐기 문장의 근거는 건드리지 않는다.
- 건드리지 않는 것: 광역 타임라인·aoe 탭, 상단 `opener`·`priority`(화면에 안 나오는 예전 필드), 특성 견본, 기본 영웅 탭, 목차·장 제목, 현장 팁(작성자 인용)·출처 목록, 영상(video).

## 규칙 (어기면 안 됨)
- skillId 는 `C:/wowmeta/site/src/data/kb-skills.json` 에 있는 것만. 찾기: 사이트 폴더에서 `npm run kb:brief -- <ID> --find <낱말>` / `--id <번호>`. KB 에 없는 스킬이 꼭 필요하면 **KB 노트를 직접 만들지 말고** 보고서 "KB 추가 필요"에 적는다(이름·번호·이유). 임의 번역 금지.
- 스킬 설명(툴팁)은 고치지 않는다. 원고 문장에서 스킬을 부를 때는 KB 의 한국어 이름 그대로 쓴다(아이콘·툴팁이 붙는다).
- 용어 고정: 네임드(보스·우두머리 금지), 쫄(졸개 금지), 딜사이클(로테이션 금지), 오프닝(오프너 금지), 쐐기(신화+ 금지), 극딜·발동·유지율. 'APL' 대신 '심크 우선순위'. 근거 없는 사용률·인기 주장 금지. '12.1' 라벨 일괄 치환 금지. 화면 글에 '사용자 확인·결정·지정' 같은 내부 작업 표시 금지.
- caption 은 짧게(대략 14자 이내, 휴대폰에서 두 줄 넘지 않게). above.when 도 짧게.
- 문장은 지금 원고의 말투(쉬운 존댓말, 짧은 문장)를 따른다. 번역투 금지. 영어 원문 인용은 넣지 않는다.
- 다른 가이드·공용 파일(GuideDetailPage.js, 검사기, guideManuscripts.js, apply-patch.cjs, digest.cjs 등)은 건드리지 않는다. 원고 파일·KB json 을 손으로 고치지 않는다.
